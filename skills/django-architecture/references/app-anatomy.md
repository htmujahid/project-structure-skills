# App anatomy

Every file an app may contain, what it holds, and when to create it.

## Always

| File | Holds |
| ---- | ----- |
| `__init__.py` | Empty. |
| `apps.py` | `AppConfig` with `name = "apps.orders"`, `label = "orders"`, `default_auto_field`, `ready()` that imports `signals`. |
| `models.py` | Models for the app's domain. |
| `migrations/` | Generated by `makemigrations`. Commit them. |

## Add on first use

| File | Create when | Rules |
| ---- | ----------- | ----- |
| `services.py` | The first write operation with a rule or side effect | Plain functions, keyword-only args, `@transaction.atomic`, raise domain exceptions. No `request`. |
| `selectors.py` | The first non-trivial read | Functions returning querysets or objects, optimized with `select_related`. No writes. |
| `managers.py` | A queryset method is reused in 2+ places | `OrderQuerySet.active()`; `objects = OrderQuerySet.as_manager()`. |
| `forms.py` | The first HTML form | `ModelForm` or `Form`; validation only. |
| `views.py` | The first HTML page | CBV or FBV per project choice; thin. |
| `urls.py` | The first route | `app_name = "orders"`; list, detail, create, update, delete names. |
| `admin.py` | Staff need to manage the data | `@admin.register(Order)`, `list_display`, `search_fields`, inlines. |
| `signals.py` | A cross-app reaction is needed | Receivers only; imported in `ready()`. |
| `tasks.py` | Work must run in background | Thin task calling a service; pass ids, not objects. |
| `consumers.py` + `routing.py` | A WebSocket endpoint exists | See async-and-realtime.md. |
| `permissions.py` | Rules reused across views | Object-level rules shared by HTML and API. |
| `exceptions.py` | Domain errors | `class OutOfStock(Exception)`; mapped to HTTP in the view/API layer. |
| `constants.py` / `enums.py` | Choices used outside models | Prefer `models.TextChoices` inside the model first. |
| `validators.py` | Reusable field validators | Referenced by migrations: never rename or move once shipped. |
| `checks.py` | Custom system checks | Registered in `ready()`. |

## Folders

| Folder | Holds |
| ------ | ----- |
| `api/` | DRF layer: `serializers.py`, `views.py`, `urls.py`, `permissions.py`, `filters.py`, `throttles.py`, `pagination.py`. Add `v1/` when versioning. |
| `templates/<app>/` | App templates, always inside an `<app>` subfolder to avoid name collisions. |
| `static/<app>/` | App assets, same namespacing rule. |
| `templatetags/` | `__init__.py` and `<name>_tags.py`; load with `{% load name_tags %}`. |
| `management/commands/` | One file per command; `__init__.py` in both `management/` and `commands/`. |
| `fixtures/` | JSON for `loaddata`, used by dev and tests only. |
| `locale/` | App-local translations, only for reusable apps. |
| `tests/` | `conftest.py`, `factories.py`, `test_*.py`. Delete the generated `tests.py`. |

## Splitting into packages

When a file grows past ~300 lines or ~5 classes, turn it into a package of the same name:

```
models/
  __init__.py     # from .order import Order; from .order_item import OrderItem; __all__ = [...]
  order.py
  order_item.py
```

- Re-export every model in `__init__.py` so Django finds them and `from apps.orders.models import Order` still works.
- Same for `services/` (one module per use case: `checkout.py`, `refunds.py`) and `views/`.
- Do not split the `migrations/` folder.

## Reusable app rule

An app meant to be shared across projects imports nothing from `core/` or other project apps, ships its own templates, and takes config via `settings.<APP>_*` with defaults in `conf.py`. Project apps need not follow this.
